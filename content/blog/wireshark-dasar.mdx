Wireshark adalah penganalisis paket jaringan — ia menangkap lalu menampilkan setiap paket yang lewat interface secara detail, sampai ke isi payload-nya. Kalau Nmap menjawab "siapa yang terhubung", Wireshark menjawab "apa yang mereka bicarakan".

Awalnya terlihat seperti lautan data, tapi dengan filter yang tepat ia jadi alat diagnostik paling tajam yang kamu punya.

## Capture yang Benar (dan Aman)

Saat memulai:

1. Pilih interface yang benar (yang terhubung ke jaringan yang ingin diamati — jangan `any` tanpa alasan).
2. Jangan langsung langsung klik tombol hijau sambil bingung. Rencanakan dulu apa yang mau dilihat.
3. Capture pada jaringan milikmu sendiri.

Di Linux, capture butuh root:

```bash
# alternatif CLI — tangkap lalu buka file-nya di Wireshark
sudo tcpdump -i eth0 -w capture.pcap
wireshark capture.pcap
```

## Filter yang Wajib Hafal

**Capture filter** (membatasi apa yang direkam — jalan di kernel):

```bash
# hanya port 80/443
tcp port 80 or tcp port 443

# hanya host tertentu
host 192.168.1.10

# semua kecuali traffic broadcast
not broadcast and not multicast
```

**Display filter** (menyaring tampilan dari capture yang sudah ada — jalan di aplikasi, yang lebih sering dipakai):

```text
# protokol
http
dns

# alamat
ip.src == 192.168.1.10
ip.dst == 8.8.8.8

# port
tcp.port == 443

# kombinasi
http && ip.src == 192.168.1.10
!(arp or dns)          # buang noise paling umum

# cari string di payload
http contains "password"
tcp.payload contains "admin"
```

Pola `ip.src == X && ip.dst == Y` adalah 80% kebutuhan harian.

## Mengikuti Arus TCP — Tombol Paling Berguna

Satu "percakapan" HTTP terdiri dari lusinan paket (SYN, ACK, data, FIN). Daripada membaca paket satu-satu:

1. Klik kanan salah satu paket → **Follow** → **TCP Stream**.
2. Wireshark menyusun ulang seluruh percakapan sebagai satu teks.

Dari sini kamu bisa langsung baca request/response HTTP mentah — termasuk apakah ada credential yang dikirim polos:

```text
POST /login HTTP/1.1
Host: contoh.com
Content-Type: application/x-www-form-urlencoded

username=admin&password=rahasia123
```

Kalau kamu melihat pola seperti ini di jaringan publik, itu masalah: kredensial dikirim tanpa enkripsi.

## Membaca Info Paket dengan Cepat

Di panel detail, urutan informasi yang paling sering dicari:

```text
Frame          → ukuran & waktu paket
Ethernet II    → MAC sumber & tujuan
Internet Protocol → IP sumber & tujuan, TTL
TCP/UDP        → port, sequence, flags (SYN/ACK/FIN/RST)
Data / Payload → isi sebenarnya
```

**Flag TCP** adalah bahasa tubuh koneksi: `SYN` memulai, `SYN-ACK` menerima, `ACK` mengonfirmasi, `RST` memutus paksa. Segala macam troubleshooting (termasuk serangan SYN flood) dimulai dari membaca flags ini.

## Dua Contoh Trouble yang Bisa Langsung Dipraktikkan

### 1. DNS lambat

```text
dns.flags.response == 1
```

Rata-rata waktu respons = masalah di DNS resolver, bukan koneksi internet. Kolom `Time` menunjukkan delay tiap paket.

### 2. Situs tidak terbuka padahal jaringan normal

Cari ke paket respons HTTP dengan status:

```text
http.response.code >= 400
```

Lalu *Follow TCP Stream* untuk melihat body error dari server.

## Statistik: Statistika Satu Klik

Menu **Statistics** menyembunyikan harta karun:

- **Protocol Hierarchy** — lihat protokol mana yang mendominasi traffic.
- **Conversations / Endpoints** — siapa bicara sama siapa, berapa banyak.
- **I/O Graph** — grafik traffic per waktu; ideal untuk melihat denyut serangan.

## Kesimpulan

Wireshark terlihat rumit karena menampilkan segalanya — triknya adalah dengan sengaja menyaring. Kuasai lima display filter utama (`ip.src`, `ip.dst`, `tcp.port`, `http`, `dns`), biasakan Follow TCP Stream, dan gunakan statistik untuk melihat gambaran besar. Setelah itu, kamu bisa "melihat" apa yang sebenarnya terjadi di jaringan.
